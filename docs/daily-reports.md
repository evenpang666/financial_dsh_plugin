# 日报、网页与推送

[← 项目首页](../README.md) · [文档导航](README.md)

交易日默认在北京时间 09:20 与 14:30 生成两期日报；持仓分析与盘中排序由用户按需发起。

## 使用流程

1. 运行 `npm start`，在 `/reports` 阅读日报或点击“生成日报”。研究提问在首页，模型由 DSH Web 统一管理。
2. 如需持仓研究，在知衡首页或 DSH Web 对话框发送持仓。例如：

```text
请保存我的持仓：
600519，名称贵州茅台，成本1280，数量100；
000858，名称五粮液，成本125，数量200。
```

智能体会调用 `set_portfolio`，将持仓保存到仅供本机使用的 `data/portfolio.json`。以后可以在 DSH Web 中发送“查看我的持仓”核对，或发送新的完整列表覆盖旧记录。

3. 定时日报不再读取或写入持仓，无论是否保存持仓，上午和下午都会生成市场内容。网页的“持仓分析”默认空白；仅保存了对应市场的持仓且点击“分析我的持仓”后，才按当前财报、估值和技术面生成分析。结果只返回当前页面，不写入定时日报。
4. 每个交易日 09:20 生成日报1；14:30 重新取数生成日报2。非交易日两个时点都跳过。
5. 日报2会逐项检查日报1候选结论：买入后从上午快照跌幅不高于 -2%，或卖出后涨幅不低于 2%，记为“明显背离”；其他结果分为“相符”“待观察”或“数据不足”。独立的持仓分析不参加定时日报复盘。
6. 原因分析只使用两次价格、当日涨跌幅、市场风险分和可得结构化事件。没有披露证据时会明确写“无法确认公司层面因果”，不会编造原因。
7. 快照保存到 `data/report-snapshots/`，累计反思保存到 `data/research-reflections.json`。后续候选筛选和单股分析会读取最近反思，以 -10 至 +5 个百分点的有限调整校准方向分，同时保留原始分、样本数和调整值。
8. 网页日报保存为 `data/reports/YYYY-MM-DD-a-morning.md` 与 `YYYY-MM-DD-a-afternoon.md`（港股使用 `hk`），可在同一日期下分别选择日报1和日报2。

## 在网页查看日报

本机访问：`http://127.0.0.1:3205/reports`，端口占用时以终端实际地址为准。

回测结果单独访问 `/backtests`。页面顶部可切换研究、日报和回测。所有页面共用本机网页服务，不需要额外开放端口。日报只呈现归档研究，不附加回测摘要。

日报页面采用“本期速览 → 市场图解 → 候选对比 → 事件线索 → 盘中复盘 → 完整正文”的阅读顺序：速览显示风险、上涨占比、候选数及归档事件数；市场图解包含涨跌平盘环形图、风险/宽度/情绪刻度、以零线区分涨跌的指数与板块图；候选热力图比较 1/5/20 日累计涨跌幅；新闻按日期去重排列；下午日报用价格变化图展示上午候选的一致性复盘。SVG 图可下载，页面支持手机阅读和浏览器打印。持仓与全市场策略部署位于下方折叠的“研究工具”，其时间独立于归档日报。回测结果在独立页面展示。

在“全市场策略部署”中选择经典交易策略或当前有效的已训练因子模型，点击“开始策略部署”。选择只影响本次网页研究任务，不修改保存设置。此入口扫描当前全市场快照中的正常交易沪深A股，不限制为训练/回测用40只候选池；剔除ST、退市标记、无成交和北交所标的，保留全部有效评分，每页50条，并显示固定规则入场状态。技术策略复用持仓排序的已完成5分钟线及预热/质量检查；逐股取数任务后台运行，页面轮询进度，20分钟未完成则停止并保留失败状态。普通固定规则与模型使用盘中快照，缺少逐股报价时间戳，与持仓的5分钟收盘特征不能直接等同。

策略部署完成后会实时通知网页，通知包含具体策略和 checkpoint。页面未手动选择策略时自动跟随新结果；已有明确选择时保留选择，并在页首显示“部署已更新 · 查看”，点击后打开对应结果。SSE 重连或漏掉通知时通过最新发布摘要恢复；网页发起的后台任务可在刷新后重新连接进度，不重新启动计算。

持仓分析完成后立即更新本页研究工具，并显示分析时间。同一市场的日报日期/时点切换或自动刷新不会清除结果；切换市场时只显示该市场本页已请求过的分析。等待期间切换同一市场的日报也不会丢弃返回结果。本次分析保留在当前页面内存中，不广播持仓数据，不自动重新读取持仓，也不写入公共日报归档；整页重新加载后需再次按需分析。

页面分别显示信号/完成时间、全市场快照数、范围内数量、有效及缺失数量；缺失标的可展开查看原因，部分成功明确标为有效子集排序。未训练、版本无效、超过30天或探索性数据超过7天的模型不进入可用模型列表，显示需训练的原因。因子模型的原训练池可能窄于全市场，扩展应用没有同口径历史验证，结果保留模型质量与范围提示。策略结果按所选策略分别保存；页面选择切换不会显示其他策略的旧候选池排序，也不自动读取持仓或执行交易。

持仓分析新增策略选择与“仓位总结”表，默认沿用保存的策略配置，也可仅在页面选择本次对照策略。三组结果分别为：现有个股规则研究配置1、所选策略在已保存持仓池上的排序配置2、逐股审查两方案差异的综合结果3。表中展示数据日、排名/评分、股票配置合计及预留现金，并可展开计算方法。工具未额外调用 LLM；智能体 skill 使用同一工具结果进行证据解释与复核，不把规则数字伪装成独立 AI 推理。

三组权重以假设研究预算100%（股票+预留现金）为分母，仅比较新增资金的研究配置；不是个人总资产仓位，不生成交易数量。市场风险上限使用现有风险档预算，单股最多25%；个股研究权重不直接使用买入倾向。策略使用相同入场规则或已有有效模型，按1/入场名次分配；未触发不等同于卖出原持仓。综合基线为逐股 `min(结果1, (结果1+结果2)/2)`，未分配部分留现金，不重新归一化放大。缺失任一持仓关键输入时整组数值留空，日期不一致时不形成数值结果3；港股暂不支持策略配置2/3。

人气榜直接读取东方财富关注排名，移除与研究无关、易失败的 `push2` 行情补全请求，设置请求超时并保留系统代理配置。来源失败时继续保留可确认的技术/基本面与价格情绪代理，页面只展示简短缺失原因，原始网络异常记录在数据服务日志。策略仅读取已完成5分钟线及通过检查的预热数据，优先本地缓存、缺失时尝试有时限的新浪分钟线；腾讯快照缺少昨收价时，尝试明确核验行情日期的新浪昨收价，不能确认日期则留空。策略取数设有整轮时限，不修改已验收的回测输入。

日报页面左侧提供固定索引列，包含图解区及随当前正文生成的二、三级标题；点击可跳转，滚动时高亮当前章节，并提供返回顶部入口。手机和平板使用可展开的紧凑目录，选择章节后自动收起；切换历史日报时索引同步更新。

所有日报图解仅使用所选报告的结构化快照，不用实时结果替换历史数据。缺失数据不绘制为零；缺少平盘家数的旧快照明确标注占比口径；纯文字历史报告保留完整正文。数据源缺失会在速览提示，正文只列可读的缺失项，原始诊断仍保留在快照。新生成的 Markdown 日报也包含“本期速览”，兼容既有归档和推送流程。

## 调度与 Webhook

网页服务在运行时使用 DSH Agent 生成与复核日报。配置 `config/daily-push.json` 的 enabled、market 和 schedules 可调整本地调度；默认北京时间 09:20 / 14:30。网页不注册系统计划任务，不自动发送 Webhook。

以下 Webhook 与 `daily_push.py` 命令属于可选的独立 CLI 流程，不应与网页调度同时运行。

默认情况下，日报1和日报2使用不同文件归档。如需远程推送，在配置中填写 Webhook：

```json
{
  "enabled": true,
  "schedules": {
    "morning": "09:20",
    "afternoon": "14:30"
  },
  "candidate_limit": 5,
  "webhook_type": "feishu",
  "webhook_url": "https://your.invalid/your-webhook"
}
```

`webhook_type` 支持 `feishu`、`wecom`、`dingtalk` 和 `generic`。更推荐把地址放入环境变量 `FINANCE_AGENT_WEBHOOK_URL`，避免把凭证写入文件。配置文件已加入 `.gitignore`。

可分别手动验证两个时点；非交易日会正常跳过，`--force` 只忽略对应时点的重复发送状态，不绕过交易日检查：

```powershell
.\.venv\Scripts\python.exe .\scripts\daily_push.py --once --session morning --force
.\.venv\Scripts\python.exe .\scripts\daily_push.py --once --session afternoon --force
```
