# 搭建 DeepSeek Harness A 股 / 港股研究智能体

本包搭建的是**只读的 A 股 / 港股分析智能体**：查询行情、计算技术指标、阅读可得财务数据，并基于客观指标给出明确买卖结论以及合计为 100% 的买入/卖出倾向。倾向百分比不是仓位或涨跌概率；系统不连接券商账户、不发送交易指令、不自动买卖。

## 1. 最终组成

```text
DeepSeek Harness (dsh)
└── dsh-finance-agent：本包提供
    ├── 20 个研究工具（检索、市场全景、同行龙头、短长期分析、交易日、日报与候选排行）
    └── 7 个内置研究 Skills
            ↑
    Python 本地数据服务（AKShare，默认 127.0.0.1:8765）
```

## 2. 需要安装的内容

| 项目 | 用途 | 是否必须 |
|---|---|---:|
| Node.js 22 LTS | 运行 dsh 和插件 | 是 |
| Python 3.11+ | 本地数据和指标服务 | 是 |
| `@deepseek-ai/dsh` | Agent 运行环境 | 是 |
| 本包 `dsh-finance-agent` | 本地行情、指标、估值工具与 Skills | 是 |
| AKShare / pandas / numpy | 数据适配与指标计算 | 是 |

请从 Node.js 和 Python 官方网站安装对应 Windows x64 版本；安装 Node 时勾选“Add to PATH”。安装后，在**新的 PowerShell**运行：

```powershell
node --version
python --version
```

## 3. 启动与使用（Windows）

先安装 Node.js 22 LTS 和 Python 3.11+；其余组件由启动器自动处理。日常使用有两种等价方式。

### 方式一：控制台简易启动（推荐）

双击项目根目录的 `control_panel.cmd`。可见命令行会依次检查 Node.js、Python、dsh、pnpm、`.venv`、Python 依赖和本地插件；缺少的组件会显示安装进度。准备完成后，启动器会使用 `.venv\Scripts\pythonw.exe` 打开控制面板。

控制面板会静默启动日报智能体、数据服务、日报页面和 DSH Web，但不会自动打开浏览器。需要检索时点击“打开 DSH Web”；需要查看归档日报时点击“打开日报”。控制面板最小化后服务会继续运行；关闭控制面板会关闭相关服务。

控制面板支持拖动边框缩放和最大化，初始尺寸按屏幕空间调整。宽窗口将网页入口与策略研究并排展示，窄窗口自动纵向排列；按钮按实际字体尺寸换行，状态与说明文字随可用宽度折行。内容超过窗口高度时，可用右侧滚动条或鼠标滚轮查看；日志保留独立滚动，Tab 切换到下方控件时会自动滚动显示。Windows 与 Linux 共用这一布局。

“网页入口”区域的“手动生成日报”会立即重新获取当前市场数据并更新本地归档：按配置的下午日报时点（默认 14:30）分界选择日报1或日报2，生成过程显示在运行日志中。手动生成不受定时推送开关和当天重复限制影响，不改变定时任务完成状态，也不执行远程 Webhook 推送；之后的定时日报仍照常执行。生成成功按 `auto_open_report` 配置打开页面；休市日会提示跳过，生成失败会保留原日报。状态检测、服务启动或其他任务进行时，该按钮禁用；生成过程中仍可打开 DSH Web、日报和回测页面。

### Linux 桌面启动

先安装 Node.js、Python 3.11+ 和 Git。在项目根目录打开终端运行：

```bash
./control_panel.sh
```

启动脚本会显示检查和安装进度；缺少 dsh、pnpm 时装入项目的 `.local/`，创建 `.venv`、安装 Python 依赖并注册插件。Linux 界面由 `/usr/bin/python3` 的系统 Tk 运行，数据和因子任务仍使用项目 `.venv`；缺少系统 Tk 时，会通过 apt、dnf 或 pacman 请求安装。界面选用系统已安装的中文字体。随后打开与 Windows 相同的控制面板，自动启用数据服务、日报页面、DSH Web 和当前登录会话的双时点日报调度器。最小化后保持后台运行；关闭控制面板会停止这些服务。Linux 调度器不会跨注销或重启自动运行，重新登录后请再次启动控制面板。

Linux 备选命令：`bash control_panel.sh`。无需界面时，`./close_agent.sh` 停止服务，`./update_agent.sh` 停止服务、拉取代码、更新 `.venv` 依赖并重新注册插件；更新后仍需重新启动控制面板。Linux 与 Windows 共享同一套行情、因子、日报和网页代码。

### 方式二：PowerShell 备选命令

在项目根目录打开 PowerShell，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap-control-panel.ps1
```

该命令与双击 `control_panel.cmd` 使用完全相同的检查、安装与启动流程，适合快捷方式失效或需要保留命令行进度时使用。

### 仅打开 DSH 对话页面

不使用本项目的日报、行情服务或控制面板时，也可以在任意工作目录的 PowerShell 中直接运行：

```powershell
dsh web
```

该命令只启动 DSH Web 对话页面，并会按 DSH 默认行为打开浏览器；不会启动日报任务、本地数据服务或日报网页。若此前已注册本项目插件，它仍会作为 DSH 的可选工具存在，但普通对话不调用这些工具即可独立使用。

首次启动后，点击“打开 DSH Web”，在“设置 → 模型”中填写 DeepSeek API Key。API Key 不要写入本项目文件或提交到 Git。

“安装 / 修复”按钮会停止服务并关闭当前控制面板，然后重新执行上述启动检查；缺失或失效的 dsh、pnpm、虚拟环境、Python 依赖和本地插件会自动修复，完成后自动重新打开控制面板。使用“更新项目”还需要系统已安装 Git，且当前目录是 Git 仓库。

## 4. 本包新增的工具

| 工具名 | 用途 | 关键限制 |
|---|---|---|
| `get_quote_snapshot` | 最近可得价格快照、成交量、PE/PB（如源提供） | 不是逐笔实时行情 |
| `get_ohlcv` | 后复权/前复权日线 | 返回数据日期和来源 |
| `get_technical_indicators` | MA、RSI、MACD、波动率、最大回撤 | 指标由程序计算，不由模型心算 |
| `get_fundamentals` | 财务分析指标 | 数据源缺失时明确报错 |
| `get_announcements` | 巨潮公告标题和链接 | 仅陈述披露事实 |
| `get_related_large_enterprises` | 按目标股所属行业和总市值识别同行龙头并查询近期公告 | 行业背景只用于核验，不按标题机械评分 |
| `get_valuation` | PE/PB 等可得估值字段 | 需要二次核对数据日期 |
| `get_saved_portfolio` | 读取本地保存的研究持仓清单 | 不连接券商或读取账户 |
| `get_portfolio_position_review` | 按需比较个股研究配置1、所选策略在持仓池上的排序配置2与综合复核3 | 假设研究预算，含现金与上限；缺失输入留空，不执行交易 |
| `set_portfolio` | 保存代码、可选成本/数量和研究备注 | 仅写入本项目 `data/portfolio.json`，不执行交易 |
| `get_market_brief` | 指数快照与可得市场快讯 | 快讯是待核验线索，不等同于价格影响 |
| `get_market_movers` | 当日涨跌幅靠前标的的研究候选池 | 异动不构成推荐或追涨信号 |
| `get_market_panorama` | 国际事件、国内政策、社交/关注情绪、大盘宽度、风险等级与参考仓位 | 情绪含价格代理；参考仓位不是个性化建议 |
| `stock_search` | 按 6 位代码或名称检索 A 股 | 名称有歧义时返回多个匹配项 |
| `get_trading_day` | 使用交易日历判断指定日期 | 每日任务在非交易日跳过 |
| `get_market_events` | 按 7 日、30 日等窗口取得事件线索 | 快讯需以公告或权威原文复核 |
| `get_candidate_ranking` | 按透明规则生成热门研究候选排行 | 基础分会按市场风险档校准，排名不是买入顺序 |
| `analyze_stock` | 汇总财务、行情、指标、估值、公告、市场覆盖状态和同行龙头动态 | 输出经市场状态校准的买入/卖出倾向和明确结论 |
| `get_daily_research_report` | `morning` 生成日报1；`afternoon` 生成日报2并复盘日报1 | 数据较多时可能需要较长时间 |
| `get_research_reflections` | 查询累计的逐股一致性、原因边界和反思 | 反思是历史反馈，不是因果或收益证明 |

AKShare 适合原型和个人研究；任何公开发布、收费服务或高频使用前，都应改接已获授权且有服务等级承诺的数据源，并审查数据授权条款。

### 港股支持

所有单股和市场工具新增 `market` 参数：`a` 为默认 A 股，`hk` 为港股。A 股代码保持 6 位；港股代码统一为 5 位，例如腾讯控股可输入 `700`、`HK:700` 或 `00700.HK`，系统会保存及请求为 `00700`。持仓可混合保存，例如：

```text
请保存我的持仓：
600519，名称贵州茅台；
00700，market=hk，名称腾讯控股。
```

在 DSH 中研究港股时，先调用 `stock_search(query="腾讯", market="hk")`，随后对单股工具传入 `market="hk"`。港股支持实时行情快照、历史日线、技术指标、东方财富可得财务指标、估值、市场全景、候选池和日报。港股公告及同行比较暂未接入 HKEX 披露源，服务会明确返回不可用，绝不会将港股代码误查为 A 股巨潮公告。

日报推送配置的 `market` 默认为 `"a"`；设为 `"hk"` 即生成港股交易日简报。持仓仅在网页点击“分析我的持仓”后按所选日报市场读取：

```json
{
  "market": "hk",
  "scheduled_time": "09:20",
  "candidate_limit": 5
}
```

A 股与港股使用不同交易日历；港股交易日判断使用恒生指数日线。当前计划任务一次只推送一个市场；若需同时保留两种日报，请为另一个市场使用独立项目目录或额外的归档策略，避免同一日期的日报文件相互覆盖。

持仓清单仅用于研究上下文，默认保存于本地 `data/portfolio.json`，不会包含券商登录信息或交易凭证。该文件已加入忽略列表；不要把它上传、共享或提交到版本库。

## 5. 每日双时点推送与反思配置

### 5.1 使用流程

1. 双击 `control_panel.cmd`，等待控制面板显示日报任务、数据服务、日报页面和 DSH Web 为“运行中”。如需对话检索，点击“打开 DSH Web”；启动时不会自动弹出网页。
2. 在 DSH Web 对话框中发送持仓。例如：

```text
请保存我的持仓：
600519，名称贵州茅台，成本1280，数量100；
000858，名称五粮液，成本125，数量200。
```

智能体会调用 `set_portfolio`，将持仓保存到仅供本机使用的 `data/portfolio.json`。以后可以在 DSH Web 中发送“查看我的持仓”核对，或发送新的完整列表覆盖旧记录。

3. 定时日报不再读取或写入持仓，无论是否保存持仓，上午和下午都会生成市场内容。网页的“持仓分析”默认空白；仅保存了对应市场的持仓且点击“分析我的持仓”后，才按当前财报、估值和技术面生成分析。结果只返回当前页面，不写入定时日报。
4. 每个交易日 09:20 生成日报1；14:30 重新取数生成日报2。非交易日两个时点都跳过。
5. 日报2会逐项检查日报1候选结论：买入后从上午快照跌幅不高于 -2%，或卖出后涨幅不低于 2%，记为“明显背离”；其他结果分为“相符”“待观察”或“数据不足”。独立的持仓分析不参加定时日报复盘。
6. 原因分析只使用两次价格、当日涨跌幅、市场风险分和可得结构化事件。没有披露证据时会明确写“无法确认公司层面因果”，不会编造原因。
7. 快照保存到 `data/report-snapshots/`，累计反思保存到 `data/research-reflections.json`。后续候选筛选和单股分析会读取最近反思，以 -10 至 +5 个百分点的有限调整校准方向分，同时保留原始分、样本数和调整值。
8. 网页日报保存为 `data/reports/YYYY-MM-DD-a-morning.md` 与 `YYYY-MM-DD-a-afternoon.md`（港股使用 `hk`），可在同一日期下分别选择日报1和日报2。

### 5.2 在网页查看日报

本机访问：`http://127.0.0.1:8766`

回测结果单独访问：`http://127.0.0.1:8766/backtests`。控制面板“网页入口”新增“打开回测”；日报与回测页面顶部也可相互切换。两个页面共用日报网页服务，无需额外启动服务或开放端口。新生成及推送的日报不再附加回测摘要；旧归档的回测摘要在日报网页读取时隐藏，原文件保留。

同一局域网的手机或电脑访问：`http://本机局域网IP:8766`。控制面板“网页入口”区域会显示当前主机的实际局域网地址，例如 `http://192.168.1.20:8766`。网页支持最新日报、历史日报切换和手动刷新。

日报汇总东方财富全球指数快照（A股、港股、美股、日本、韩国，逐项保留行情时间）、A股半导体/存储/光通信概念板块、财经新闻和事件线索，并展示市场宽度与风险研判。网页用条形图可视化指数和板块涨跌幅；“中长线 / 短线 / 超短线”切换查看基于有限候选池的不同证据门槛观察名单。缺少财报或技术证据时该周期可能为空，绝不补造推荐。港股日报的主题板块目前仍是 A 股概念板块，已在页面标注。公开资料中未确认“市场魔方助手”稳定开放接口，因此未直接抓取其页面，使用可追溯的东方财富/AKShare 上游接口。各市场休市时间不同，跨市场快照不可视为同时交易。

日报生成成功后，主机会自动使用默认浏览器打开对应的日报1或日报2。若不希望自动弹出，可在 `config/daily-push.json` 中设置 `"auto_open_report": false`。

日报页面采用“本期速览 → 市场图解 → 候选对比 → 事件线索 → 盘中复盘 → 完整正文”的阅读顺序：速览显示风险、上涨占比、候选数及归档事件数；市场图解包含涨跌平盘环形图、风险/宽度/情绪刻度、以零线区分涨跌的指数与板块图；候选热力图比较 1/5/20 日累计涨跌幅；新闻按日期去重排列；下午日报用价格变化图展示上午候选的一致性复盘。SVG 图可下载，页面支持手机阅读和浏览器打印。持仓与全市场盘中排序位于下方折叠的“研究工具”，其时间独立于归档日报。回测结果在独立页面展示。

在“全市场盘中排序”中选择固定交易策略或当前有效的已训练因子模型，点击“开始盘中排序”。选择只影响本次网页研究任务，不修改控制面板设置。此入口扫描当前全市场快照中的正常交易沪深A股，不限制为训练/回测用40只候选池；剔除ST、退市标记、无成交和北交所标的，保留全部有效评分，每页50条，并显示固定规则入场状态。技术策略复用持仓排序的已完成5分钟线及预热/质量检查；逐股取数任务后台运行，页面轮询进度，20分钟未完成则停止并保留失败状态。普通固定规则与模型使用盘中快照，缺少逐股报价时间戳，与持仓的5分钟收盘特征不能直接等同。

页面分别显示信号/完成时间、全市场快照数、范围内数量、有效及缺失数量；缺失标的可展开查看原因，部分成功明确标为有效子集排序。未训练、版本无效、超过30天或探索性数据超过7天的模型不进入可用模型列表，显示需训练的原因。因子模型的原训练池可能窄于全市场，扩展应用没有同口径历史验证，结果保留模型质量与范围提示。策略结果按所选策略分别保存；页面选择切换不会显示其他策略的旧候选池排序，也不自动读取持仓或执行交易。

持仓分析新增策略选择与“仓位总结”表，默认沿用控制面板所选策略，也可仅在页面选择本次对照策略。三组结果分别为：现有个股规则研究配置1、所选策略在已保存持仓池上的排序配置2、逐股审查两方案差异的综合结果3。表中展示数据日、排名/评分、股票配置合计及预留现金，并可展开计算方法。工具未额外调用 LLM；智能体 skill 使用同一工具结果进行证据解释与复核，不把规则数字伪装成独立 AI 推理。

三组权重以假设研究预算100%（股票+预留现金）为分母，仅比较新增资金的研究配置；不是个人总资产仓位，不生成交易数量。市场风险上限使用现有风险档预算，单股最多25%；个股研究权重不直接使用买入倾向。策略使用相同入场规则或已有有效模型，按1/入场名次分配；未触发不等同于卖出原持仓。综合基线为逐股 `min(结果1, (结果1+结果2)/2)`，未分配部分留现金，不重新归一化放大。缺失任一持仓关键输入时整组数值留空，日期不一致时不形成数值结果3；港股暂不支持策略配置2/3。

人气榜直接读取东方财富关注排名，移除与研究无关、易失败的 `push2` 行情补全请求，设置请求超时并保留系统代理配置。来源失败时继续保留可确认的技术/基本面与价格情绪代理，页面只展示简短缺失原因，原始网络异常记录在数据服务日志。策略仅读取已完成5分钟线及通过检查的预热数据，优先本地缓存、缺失时尝试有时限的新浪分钟线；腾讯快照缺少昨收价时，尝试明确核验行情日期的新浪昨收价，不能确认日期则留空。策略取数设有整轮时限，不修改已验收的回测输入。

日报页面左侧提供固定索引列，包含图解区及随当前正文生成的二、三级标题；点击可跳转，滚动时高亮当前章节，并提供返回顶部入口。手机和平板使用可展开的紧凑目录，选择章节后自动收起；切换历史日报时索引同步更新。

所有日报图解仅使用所选报告的结构化快照，不用实时结果替换历史数据。缺失数据不绘制为零；缺少平盘家数的旧快照明确标注占比口径；纯文字历史报告保留完整正文。数据源缺失会在速览提示，正文只列可读的缺失项，原始诊断仍保留在快照。新生成的 Markdown 日报也包含“本期速览”，兼容既有归档和推送流程。

如果其他设备无法访问，请确认两台设备连接同一局域网、Windows 网络类型为“专用网络”，并以管理员 PowerShell 运行：

```powershell
.\scripts\configure-lan-firewall.ps1
```

该命令只允许专用网络的本地子网访问 TCP 8766 端口。虽然新定时日报不再包含持仓，但历史归档可能仍有旧持仓内容，而且局域网用户可以主动点击“分析我的持仓”，因此不建议在公共 Wi-Fi 或不可信局域网开放。

### 5.3 调度与 Webhook

首次由控制面板启动日报智能体时，会将 `config/daily-push.example.json` 复制为不纳入 Git 的 `config/daily-push.json`，并注册 Windows 计划任务 `DSH A-Share Pre-open Research`。同一任务包含北京时间 09:20 与 14:30 两个触发器；数据服务会再次核验交易日，因此周末和休市日不会推送。若系统不允许注册任务，启动器会自动退回为当前登录会话内的后台调度器。

控制面板还会注册 `DSH A-Share Report Site` 登录任务，使日报网页在用户登录 Windows 后自动运行。

默认情况下，日报1和日报2使用不同文件归档。如需远程推送，在配置中填写 Webhook：

```json
{
  "enabled": true,
  "schedules": {
    "morning": "09:20",
    "afternoon": "14:30"
  },
  "candidate_limit": 5,
  "webhook_type": "feishu",
  "webhook_url": "https://your.invalid/your-webhook"
}
```

`webhook_type` 支持 `feishu`、`wecom`、`dingtalk` 和 `generic`。更推荐把地址放入环境变量 `FINANCE_AGENT_WEBHOOK_URL`，避免把凭证写入文件。配置文件已加入 `.gitignore`。

可分别手动验证两个时点；非交易日会正常跳过，`--force` 只忽略对应时点的重复发送状态，不绕过交易日检查：

```powershell
.\.venv\Scripts\python.exe .\scripts\daily_push.py --once --session morning --force
.\.venv\Scripts\python.exe .\scripts\daily_push.py --once --session afternoon --force
```

### 5.4 更新项目

可以点击控制台中的“更新项目”，或双击项目根目录的 `update_agent.cmd`。更新会先停止全部项目服务和日报任务，再执行 `git pull --ff-only`，更新 `.venv` 中的 Python 依赖，并重新注册本地 `dsh-finance-agent` 插件；不会更新 dsh 或 pnpm。更新完成后所有服务保持关闭；关闭并重新打开控制台后会自动启用全部服务。`config/daily-push.json`、持仓、历史日报和反思数据均不会被 Git 覆盖。

若存在未提交的受版本控制文件修改，Git 会安全地拒绝可能造成覆盖的更新；根据窗口中的提示处理修改后重新双击即可。

### 5.5 A 股盘中因子研究

控制面板有三个按钮，Windows 和 Linux 操作相同：

推荐用法：先在控制面板的“策略 / 模型”中选择 XGBoost、Elastic Net 或固定规则策略。训练、回测和排序都读取此选择，默认 XGBoost。因子模型每次只训练所选的一种；切换模型后分别读取各自保存的模型，所选模型尚未训练时会提示先训练。启用智能体后，每个工作日 12:00 检查所选因子模型的每周训练；本周成功一次便跳过，失败在下个工作日重试。固定规则策略无需训练，也不执行每周训练。回测信号时点默认 14:00，可选 09:35、10:30、11:30、13:30、14:30、14:50。点击“一键回测”时，如缺少逐日历史数据，控制面板会提示并自动下载、验收，成功后继续回测；下载或验收失败时不会生成收益。关闭控制面板后每周训练继续运行；安装或更新项目时会暂停，重新启用智能体后恢复。

历史数据准备：若本机 `config/tushare.token` 存在且能读取全市场日线，优先使用 Tushare；文件缺失、Token 无效或接口不可用时，自动改用 BaoStock 的逐日历史证券名单及未复权全市场日线，并尽可能用 AKShare 交易日历交叉核对。BaoStock 仍提供上市资料、逐日 ST/停牌状态、公司行为与未复权 5 分钟线；无需 Tushare 分钟线权限。Token 文件仅一行，已由 Git 忽略；自动选择数据源不读取 `TUSHARE_TOKEN` 环境变量。执行：

本仓库的 `.gitignore` 忽略所有 `*.token` 文件；本机已启用 `.githooks` 拦截误提交和误推送。新克隆仓库可运行 `git config --local core.hooksPath .githooks` 启用相同保护。不要用 `git add -f` 或 `--no-verify` 绕过这些保护。

```powershell
.venv\Scripts\python.exe scripts\factor_data_prep.py --start 2025-09-08 --end 2026-10-09
```

Linux 在项目目录运行：

```bash
./.venv/bin/python scripts/factor_data_prep.py --start 2025-09-08 --end 2026-10-09
./.venv/bin/python scripts/factor_lab.py backtest
```

首条命令需要联网获取历史数据；`--end` 应设为已收盘的交易日。只有数据验收通过并生成 `data/factor-lab/source-manifest.json` 后，第二条命令和控制面板的“一键回测”才可运行。已有的“一键训练”分钟线缓存不会自动生成这两个逐日文件。每只股票首次进入历史股票池前，还需下载前一交易日的完整分钟线，用于昨收价和跳空特征；验收会独立检查这一天。旧清单未记录 `feature_warmup_validated` 时，控制面板自动补齐并重新验收。

分钟线缓存即使已有 48 根，也需通过时间戳、数值、OHLC 与成交均价检查；分钟成交额合计不得超出对应日线总额的 1% 容差。BaoStock 返回异常交易日时，自动尝试新浪未复权 5 分钟线替换整日，完整校验后才写入缓存。备用源缺少有成交的 K 线时停止修复；只有原始源明确记录零成交的窗口，才可沿用该日备用源此前的收盘价。原始异常数据、备用回复和修复记录保存在 `data/factor-lab/source-cache/minute-repairs/`；验收报告会列出股票、日期、具体原因及异常样例。“已检查…失败 0”是取数步骤的进度，最终是否可回测以验收结果为准。

脚本按数据源分别缓存日线，按前一交易日成交额重建每日前 40 只股票池，检查历史名单、股票池、公司行为和完整 5 分钟线，通过验收后才发布 `universe-history.csv`、`market-state.csv` 和带 SHA-256 校验值的 `source-manifest.json`。首次使用公共数据需逐日下载证券名单、逐股下载全市场日线，可能耗时较久；中断后可重复执行。`--skip-minutes` 只验收已有分钟线，`--offline` 使用上次采集的日线来源缓存。涨跌停价依交易规则、未复权前收盘价及公司行为重建，并非交易所原始限价；若行情超出重建价格，脚本停止并要求补充核实。数据源历史回填不能证明供应商在过去交易时点实际已经交付全部数据，因此结果应标为“历史供应商数据重建”，不能当作当时真实留档的可交易信号。

已确认的 `601091 / 2026-09-21` 历史异常有随代码分发的[核验数据与来源记录](data-corrections/minute/README.md)，新用户无需复制他人的运行缓存，且不依赖新浪近期接口继续覆盖该日。控制面板会比较输入文件与来源清单中的哈希，缓存变动后自动重新准备。回归测试使用独立临时目录和受控供应商回复，覆盖空缓存首次准备、部分下载后续传、首次入池预热、备用源不可用、修正文件损坏、准备失败不发布数据及不启动回测；这些测试不意味着外部数据服务永远正常。

1. **一键训练**：验收通过后从逐日历史股票池训练；未准备历史数据时从当前成交额前 40 只 A 股建立探索性候选池（盘前成交额不可用时改用总市值），通过 BaoStock 回填近 400 自然日的 5 分钟行情，并用东方财富或新浪补齐近期行情，增量保存在 `data/factor-lab/bars/`。在选定时点计算盘中五项特征；标签为预留一根完整 K 线后，在随后一根 K 线按 VWAP 买入至下一交易日同一窗口 VWAP 卖出的价格变化。按交易日拆分训练、验证和留出日期，评估用户指定的 XGBoost 或 Elastic Net；全程只运行所选模型，模型仍标为探索性。训练不会自动运行回测或发布旧版绩效。

训练时优先使用东方财富 A 股快照；若连接失败则尝试新浪快照。XGBoost 的训练、回测拟合与排序预测会先探测 CUDA，运行环境中有可用 NVIDIA GPU 时使用 GPU，CUDA 不可用或运行失败时回退 CPU；Elastic Net 与数据采集仍由 CPU 执行，日志会显示 XGBoost 的计算设备。历史 BaoStock 回填串行进行，近期东方财富分钟线最多 2 路并发，新浪分钟线备用源串行访问。数据不足或模型训练失败时保留已发布的旧模型，不发布不完整模型；若所选模型验证期未达正向门槛，则发布带明确警告的探索性模型。首次回填 40 只股票的一年以上分钟线可能较慢；日志显示每只股票的累计交易日数和失败原因。
若两个实时快照源都不可用，“一键训练”可沿用最近 30 天的已缓存股票池和分钟线；命令行 `python scripts/factor_lab.py train-cached` 可明确使用本地缓存重训。缓存训练仍带有当前股票池的历史选股偏差。
2. **一键回测**：发现本地缺少逐日历史股票池、交易状态或验收清单时，先自动运行历史数据准备流程；准备完成后只读取通过来源清单校验的本地分钟线、`data/factor-lab/universe-history.csv` 和 `data/factor-lab/market-state.csv`，不发布模型。股票池文件每行有 `day,symbol,known_at`；交易状态文件每行有 `day,symbol,has_price_limit,limit_up,limit_down,split_ratio,cash_dividend,dividend_pay_date,stock_credit_date,is_st,is_suspended`。历史数据缺失、重复、非停牌股票缺少完整行情或哈希校验失败时，回测拒绝生成绩效。因子回测固定使用所选模型，沿用相同的时间拆分与成熟标签重拟合规则；固定规则策略无需拟合。两种因子模型和八种固定策略均使用 120 个交易日预备期后的共同评估区间；下单前用信号 K 线价格和金额确定订单，预留一个完整 K 线后按下一根 K 线的 VWAP 与成交参与率模拟部分成交。默认 14:00 信号对应 14:05–14:10 执行窗口；科创板买入至少 200 股，其他股票按 100 股；执行 T+1、涨跌停阻断、手续费和滑点。现金红利净额在到账日后计入可用现金；送转股在实际上市交易日前计入资产，但不能卖出。保存 `data/factor-lab/backtests/<时间>/summary.json`、`equity.csv`、`trades.csv`、`folds.json`。
3. **一键排序**：控制面板保留已确认 A 股交易日、09:35–11:30 或 13:00–15:00 的候选池研究排序，使用面板所选策略，固定规则仅展示触发入场的前20名并独立归档。日报网页使用上文的独立“全市场盘中排序”入口，可直接在网页选策略并启动任务，展示全部有效评分。

4. **回测全部策略**：一次加载已验收数据，分别评估两种因子模型及八种固定策略，保存每项独立的结果与批次清单。某项失败会记录原因并继续其他策略，不生成该项绩效。训练、回测与排序过程中仍可打开 DSH Web、日报和回测页面；状态检测期间所有按钮及选择框禁用。

固定规则为 A 股只做多的盘中基础策略，信号只读取截至所选时点的行情；每天选择最多 5 只，按统一的延后 VWAP、每日重审、仍在前五名则保留持仓、离开前五名后提交卖单的规则模拟成交，无信号时保留现金。参数未根据评估期调优：

| 选择 | 标识 | 入场 / 排名规则 |
| --- | --- | --- |
| XGBoost 因子模型 | `xgboost` | 只拟合 XGBoost，按预测分数排名；CUDA 优先、CPU 回退 |
| Elastic Net 因子模型 | `elastic_net` | 只拟合 Elastic Net，按预测分数排名；CPU 运行 |
| VWAP 均值回归 | `mean_reversion` | 价格低于信号时点日内 VWAP 至少 0.5%，按负偏离排名 |
| 盘中动量 | `momentum` | 开盘以来涨幅至少 0.5%，按涨幅排名 |
| 日内区间突破 | `breakout` | 价格位于截至信号时点区间顶部 5%，振幅至少 1%，且开盘以来上涨 |
| 均线金叉 | `ma_crossover` | 5 分钟 SMA(5) 上穿 SMA(20)，按正偏离排名 |
| MACD 金叉 | `macd` | 5 分钟 MACD(12,26,9) 的 DIF 上穿 DEA，按价格归一化柱差排名 |
| RSI 超卖反弹 | `rsi_rebound` | Wilder RSI(14) 从 30 以下回升到 30 或以上，按回升幅度排名 |
| 布林带回归 | `bollinger_reversion` | 收盘价从 20 根、2 倍总体标准差的下轨外回到带内，按回归幅度排名 |
| 唐奇安通道突破 | `donchian_breakout` | 收盘价上穿此前 20 根 K 线最高价；通道排除信号 K 线 |

固定策略共 8 个，另有 XGBoost、Elastic Net 两种因子模型，共 10 项可选。新增技术策略使用已完成的 **5 分钟 K 线**，不是 5/20 日线策略；每个交易日以前一有效交易日的 48 根 K 线预热，EMA 与 RSI 使用均值初始化，历史价格只按信号日前已发生的公司行为调整。金叉和回归须在选定的信号 K 线上触发，因此可能出现无信号日期。实时排序自动取得所需分钟线并排除尚未完成的 K 线，使用独立 `live-bars/` 缓存；完整定义及指标依据见[固定策略说明](docs/fixed-strategies.md)。

命令行也可指定本次策略，不改控制面板保存的选择：`python scripts/factor_lab.py train --strategy elastic_net`、`python scripts/factor_lab.py backtest --strategy mean_reversion`、`python scripts/factor_lab.py rank --strategy momentum`；`python scripts/factor_lab.py backtest-all` 回测全部十项。设置保存在 `config/factor-lab.json` 的 `strategy` 字段，示例见 `config/factor-lab.example.json`。

独立回测页面 `http://127.0.0.1:8766/backtests`（局域网访问使用本机 IP）展示各策略最新的收益、最大回撤、Sharpe 与交易次数；可切换历史记录查看累计净值、回撤曲线，并下载净值 CSV 和交易明细。完成回测后自动通知已打开的页面；未打开时下次访问仍可读取结果。每条记录标明评估日期和信号时点，不同日期、时点或数据版本的结果应分别比较。历史自动选模结果保留在历史下拉列表中，单独标为历史因子回测。

回测引擎版本 4 已修正日内区间突破阈值并加入五分钟技术指标策略；沿用版本 3 冻结全部订单的信号期预算，补齐过户费、历史印花税率和保守分红税预留；结果包含费用/滑点加倍与 2% 成交参与率压力测试。开始回测前会保存策略、时点、数据和代码哈希的研究计划，所有比较仍是探索性研究，未做多重检验校正。回测页面保留并标记旧引擎结果，修改前的结果需重新运行；六类偏差的详细检查与剩余限制见 [回测审计](docs/backtest-audit.md)。

旧版固定股票池回测保存在磁盘用于审计，但回测页面不再展示其绩效。新版逐日股票池与交易状态需要可靠历史数据源，不能从现有 40 只股票缓存倒推。因子回测重放指定模型的逐窗口训练规则，不代表当前发布模型权重的历史收益。固定规则回测使用预先确定的参数。5 分钟 OHLCV 没有真实盘口，VWAP、成交参与率和滑点仍为假设；停牌持仓按最近收盘价估值，末日持仓不强制卖出。实时快照没有逐股报价时间戳，实时排名与回测特征可能存在时差，因此排名不作为收益概率或买入指令。

## 6. 内置 Skills

`dsh-finance-agent/skills/` 中的文件随插件自动加载：

| Skill | 何时使用 |
|---|---|
| `a-share-research` | 用户要求研究、比较或复盘 A 股时 |
| `investment-risk-control` | 每次涉及市场判断或动作建议时 |
| `earnings-and-announcement-analysis` | 解读财报、业绩预告和公告事件时 |
| `quant-strategy-research` | 要求回测或评估规则时 |
| `portfolio-daily-review` | 日报1、日报2盘中对照或每周复盘已保存持仓时 |
| `market-event-briefing` | 汇总每日/每周市场大事并分析可能传导路径时 |
| `daily-stock-candidate-screen` | 生成每日待研究候选池时 |

分析结果会使用“建议买入 / 建议持有观察 / 建议卖出 / 信息不足，暂缓决策”，并输出买入、卖出倾向百分比。百分比是可复核的证据方向评分，不是建议仓位，也不会触发交易。

市场全景以全市场涨跌家数、5/20日参与度、涨跌停分布和关注榜构造宽度与情绪代理，并把最近事件拆为国际事件、国内政策和其他事件。综合风险档产生统一的市场调整值（-20 至 +12 个百分点），同时校准持仓股与候选股的基础买入倾向。报告会保留基础分和调整值，便于复核。参考仓位仅是分散组合的市场风险预算区间，不针对个人资产配置。

单股分析同时返回 `historical_reflections` 与 `market_context`，逐项标记国际事件、国内政策、大盘宽度和社交/关注数据的覆盖状态、窗口、截止日期及缺失原因，防止数据源失败时被误读为“中性”。`related_large_enterprises` 会识别目标公司的东方财富行业，从行业成分中按总市值选取最多 3 家同行龙头，并查询其近 30 日巨潮公告；这些公告只作为行业背景与风险核验，不直接改变个股评分。

```text
请研究 600519，数据截止到最近一个可得交易日。
先调用行情、技术指标、财务和公告工具；然后输出：
```

## 8. 数据时效和责任边界

- 工具的 `as_of` 字段是唯一可依赖的数据时间；没有该字段就不要把数据说成实时。
- 行情、复权、停牌、除权除息、公告归档都可能影响结论；需要交易用途时请从权威/授权数据源复核。
- 历史回测不代表未来结果。回测必须包含手续费、滑点、涨跌停、停牌与样本外验证。
- 本包输出的是程序化买卖建议和证据倾向分，不是持牌证券投资咨询；百分比不是仓位或收益概率，使用者自行作出并承担投资决策。

## 9. 常见问题

**`dsh` 不是内部或外部命令**：关闭并重开 PowerShell；确认 Node.js 已加入 PATH，然后重新双击 `control_panel.cmd` 或运行“方式二”的备选命令。启动引导会自动安装缺失的 dsh。

**工具提示无法连接数据服务**：点击控制面板“刷新”检查服务状态；若数据服务未运行，关闭并重新打开控制面板。也可运行 `Invoke-RestMethod http://127.0.0.1:8765/health` 排查端口占用。

**AKShare 查询失败或字段变化**：升级依赖 `pip install --upgrade akshare`。若仍不稳定，应在 `scripts/stock_data_server.py` 的 Provider 层替换为 Tushare 或企业数据源；不要让模型以旧缓存补写数据。

**需要美股**：须新增经授权的对应市场数据适配器；不要将 A 股或港股代码规则用于其他市场。
